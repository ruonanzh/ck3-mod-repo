# CK3 modding docs index

A curated map of the knowledge layer under `docs/`. **Load selectively.** Read this index first. Then open only the one or two pages that the current task needs, instead of pulling the whole `docs/` directory into context.

## Lookup hierarchy (which source is authoritative for what)

| You need | Source |
|---|---|
| Exact vanilla object definitions, field values, and loc keys | `game-scripts/vanilla/game/` — the modding context that `sync_game_scripts` generates (a copy of the game directory, so the scripts sit one level down). Never grep the install directory instead |
| The parameters of one effect, trigger, modifier, or scope, and the categories and cross-references the dump does not carry | [`wiki/`](wiki/README.md), the shipped snapshot of the wiki reference lists |
| The **exact scope** of an effect, trigger, or modifier in the dumped build | `docs/script_docs/`: each effect and trigger entry carries `Supported Scopes:`, and each modifier entry carries `Use areas:`. The wiki lists are older (some state 1.12), so the dump wins on scope. An effect or trigger entry also carries a description, often on several lines. A modifier or on_action entry carries no description. |
| The GUI data types, promotes, and functions | `docs/data_types/`, from `node scripts/dump-script-docs.mjs --command=dump_data_types` |
| "How do I add a building / trait / decision / …" | [`wiki/`](wiki/README.md): one page per content kind. There is no building page. [`wiki/Holdings_modding.md`](wiki/Holdings_modding.md) covers it |
| Whether a wiki page exists at all (including the pages not shipped) | [`wiki/INDEX.md`](wiki/INDEX.md) — one row per page, with `Local = yes/no` |
| Whether a name still exists in the **installed** version | `docs/script_docs/*.log`, generated by `node scripts/dump-script-docs.mjs` and committed. It is exact for the build it was dumped from, so it beats the `wiki/` snapshot, and a game patch can make it stale |
| Script language rules (syntax, scopes, variables, iterators, templates) | [`wiki/Scripting.md`](wiki/Scripting.md) |
| Mechanics concepts and how-to method (mod API) | the official wiki (ck3.paradoxwikis.com). When it is unreachable, the snapshot under `wiki/` is the offline substitute |
| The modding conventions and the reason behind them | [`ck3-modding-conventions.md`](ck3-modding-conventions.md) |

- **Start here:** [`ck3-modding-conventions.md`](ck3-modding-conventions.md). This cheat-sheet covers override (LIOS/FIOS), load order, localization, the `descriptor.mod`/`.mod` metadata, and the entry mechanisms. It answers most modding questions on its own. Read the pages below only when you need more depth.

## How a player request becomes a mod

The two stages and their steps are in `.pi/skills/mod-creator/SKILL.md`. Stage 1 settles the request and the mount point. Stage 2 writes the mod and checks it.

Choosing the mechanism is a decision, and the search locates a name. The form and the parameters of a call come from the reference lists in [`wiki/`](wiki/README.md). The exact scope comes from `docs/script_docs/`.

`validate_mod` checks syntax, conventions, and names. Sections 3, 4, 5, and 9 of [`ck3-modding-conventions.md`](ck3-modding-conventions.md) state what it checks, and section 9 states what it does not.
